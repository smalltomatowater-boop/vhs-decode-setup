# `--use_saved_levels` 検証記録（本番標準化）

- 検証日: 2026-11-13
- 標準化した日: 2026-11-13
- 素材: tape05r（VHS / NTSC / 7分37秒 / FANATIC◇CRISIS「Truth」）
  - 原本RF 13,088,325,632 バイト。**同一RFを2通りの設定でデコードして比較**
- 変更箇所: `bin/vhsfinish:196` / `bin/vhstool:179`（並列） / `bin/vhstool:234`（単発）

## 検証の範囲（重要）

**この記録はテープ1本・7分37秒（27,390コマ）での測定値であり、
2時間テープでの長時間挙動は未検証。** マスターの判断で、未検証のまま
標準化した。長いテープで前半と後半の明るさが食い違うようなら、
まずこの設定を疑うこと。

並列デコード（`vhstool pbuild`）は**区間ごとに別プロセス**で走るため、
`--use_saved_levels` は各区間の先頭フィールドでレベルを決める。
区間の境目でレベルが食い違う可能性があり、**そこは未検証**。
境目に段差が見えたらここを疑うこと。

## 人による確認

**2026-11-13、マスターが `[FANATIC◇CRISIS]Truth_標準.mp4` を全編通して
目で見て「問題なし」。** これが唯一の本当の合格である。

壊れていた旧版は `vhsverify` の自動検査15項目を**全部通っていた**。
自動検査はファイルが壊れていないかしか見ておらず、絵が壊れていないかは
見ていない。数値指標（帯の幅・色差σ）も、作った本人が2回続けて
「直った」と誤判定している。**納品前に人が1本通して見る工程は省けない。**

## 何を直す設定か

`vhs-decode --help` の記述:

> Try re-using video levels detected from the first decoded fields
> instead of re-calculating each frame. Will be done by default once well tested

**上流自身が「いずれ標準にする」と書いている設定。**
既定（毎コマ再測定）は白飛びした場面でレベル測定が狂い、復調ごと壊れる。

## 情報を壊していないことの確認

**1. 傷の件数が変わらない。** 本編 298 → 304（±2%）。同一RFなので
この差は復号の揺らぎ。設定が傷を隠しているなら件数は減るはず。減っていない。

**2. テープ終端の虹色だけが残る。** 本編の17区間が全部消えて、終端の1区間
（439.456〜457.106秒、いろどり51.8 / ざらつき18.0）はそのまま残った。
彩度を無差別に殺す設定なら終端も消える。消えていない。

**3. 正常な絵の明るさが動かない。** 1秒ごとに全編を標本化し、
真っ黒・真っ白のコマを除いた 380〜381コマで測った:

| | 平均輝度 | 黒点(1%) | 白点(99%) | 前半 | 後半 |
|---|---|---|---|---|---|
| 旧 | 91.936 | 1.000 | 185.000 | 88.992 | 95.438 |
| 新 | 92.698 | 1.000 | 184.000 | 90.401 | 95.447 |
| 差 | +0.762 | 0.000 | −1.000 | +1.409 | **+0.009** |

**時間が経つほど差が縮む。** レベルが漂流するなら逆になる。
（ただし観測は7.6分のみ。2時間での挙動は別物かもしれない）

## 納品物での再現（圧縮後も判別できるか）

しきい値は中間マスターで決めたもの。納品mp4はノイズ低減と H.264 圧縮を
通るため、同じ数字が出る保証はない。**答えの分かっている納品物2本で確認した。**

| mp4（640x480 / 59.94 / progressive） | 帯3%超 | 帯99%分位 | いろどり95% | ざらつき95% |
|---|---|---|---|---|
| `[FANATIC◇CRISIS]Truth_標準.mp4`（旧・壊れ） | **338** | 15.23% | 34.06 | 4.42 |
| `tape05_標準.mp4`（新・修正後） | **4** | 0.00% | 11.48 | 0.63 |

新側に残る4コマはテープ終端。**圧縮を通しても判別できる。**
ただし `vhstear.py` には `--pre null` を渡すこと
（既定の `bwdif+crop=746` は、すでに progressive / 640幅の納品物には使えない）。

## 副作用で捨てたもの

この設定を標準化したことで、以下は**役目を終えた**:

- `profiles/standard-v3.sh` / `profiles/contrast-v3.sh` — 納品段での色消し
- `bin/vhstear.py` の修復用途 — 裂けコマの差し替え
  （**検出器としては残す。** 再発の見張りに使う）
- `docs/verify-standard-v3.md` — v3 の検証記録（事情を残すため削除しない）

## 恩恵を受けられないもの

tape01〜04 / 06 / 07 は**原本RFを削除済み**のため、再デコードができない。
直すには再キャプチャが必要。tape05 が直ったのは 2026-11-12 に
物理テープを録り直して tape05r を得ていたからである。
