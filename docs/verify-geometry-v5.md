# 画角と画素比を測り直す（v5）

2026-11-13。マスターの「縮める理由あるの？ないよね」から始まった。
v2〜v4 は 746 を 640 に縮めて正方画素で出していた。その是非を測った。

## 746 という幅は何なのか

vhs-decode は 13.5MHz ではなく **4fsc(14.3181818MHz)** で刻む。

    4fsc / 13.5MHz = 35/33
    BT.601 の有効画面 704標本 @13.5MHz = 52.1481us
      同じ時間を 4fsc で数えると 704 × 35/33 = 2240/3 = 746.67 標本

**640(正方画素) = 704(13.5MHz) = 746.67(4fsc) は全て同じ横幅**であり、
画素の大きさが違うだけ。マスターの 760標本は 716.6@13.5MHz ≒ 717 で、
746 との差（約14標本）がブラウン管で見えなかった余白にあたる。

## 画素比は 6:7（320:373 ではない）

    13.5MHz の画素比  640/704 = 10/11 = 0.909091   （教科書どおり）
    4fsc   の画素比  640/(2240/3) = 6/7 = 0.857143
      10/11 × 33/35 = 6/7   ぴったり約分できる

一度 320:373 を使ったが、あれは「746標本をちょうど4:3と見なす」近似で
**0.0894% 横に広かった**。746 の正確な値は 746.67 標本である。

**`setsar` には `max` の罠がある。** 既定値は 100 で、320/373 を渡すと
85:99（表示比 1.33438）に丸められた。実測で踏んだ。6:7 は丸められない。

## 縮めても失われないが、縮める理由も無い

tape05 の64コマで横方向のスペクトルを取った（有効走査746画素=52.66us）:

    3.00MHz(158サイクル) 以上  0.416%   ← VHSの輝度帯域の上限
    6.08MHz(320サイクル) 以上  0.0177%  ← 640 に縮めると落ちる範囲
    7.08MHz(373サイクル) 以上  0.0003%

落ちるのは -46dB のノイズで、絵ではない。
同じ表示サイズに揃えて見比べると、横方向の隣接画素差は
**640起源 1.402 / 746起源 1.413、差 0.8%**。等倍では判別できない。

**つまり「縮めると解像度が落ちる」は成立しない。**
それでも 746 のまま出すことにしたのは、再標本化を通さずに済むため。

### 画素が増えても画は広がらない（証拠）

640版を746に戻して746版と引き算すると平均差 1.97/255。
わざと1画素ずらすと 3.25 になる。**ズレすら無い**＝同じ範囲を見ている。
両端の列の明るさも一致（左 107.1 対 106.7、右 13.8 対 13.0）。

## 切り出しの位置と高さ（tape05・120コマ平均）

それぞれの端の近くを基準にした相対値:

    左   x=0 89.7%  x=1 95.9%  x=2 99.4%  x=3 101.4%
    右   x=746 94.9%  x=747 92.3%  x=748 88.8%  x=749 84.6%  x=752 67.3%
    上   y=0,1 床   y=2 62.6%  y=3 67.1%  y=4 96.4%  y=5 99.8%
    下   y=479 95.9%  y=480〜485 約73%（ヘッド切替の帯）  y=486 57%  y=487 床

**v4 までの `746:480:4:4` は右に3画素ずれていた。** 右端の薄い3列
（92/89/85%）を拾い、左の良い3列（96/99/101%）を捨てていた。
また下はヘッド切替の帯を4行ぶん含んでいた。

v5 は残る画素が全て 95.9% 以上になる窓を取る:

    CROP="crop=746:476:1:4"
    SCALE="scale=746:476:in_range=pc:out_range=tv,setsar=6/7"
      → 746x476 画素比6:7 ＝ 正方画素で 639.4x476、表示比 1.34334

4:3 より僅かに平たいのは、下の帯を削ったぶん縦が減っているため。
これが正しい。

## 検査器を直した

`bin/vhsverify` は 640x480 固定で見ていた。画素比を掛けて正方画素に
直した幅が 638〜641、高さが 470〜481 に入るかで見るようにした。
v2〜v4（640x480 画素比1:1 → 640.0）も v5 も通る。

## 参考: tbc-video-export 自身の表示寸法

書き出しの最後の mkvmerge は `--display-dimensions 0:648x488` を付ける。
760標本を648正方画素と見なす計算で、こちらの 6:7（760なら651.4）とは
0.5% 違う。マスターの mkv のタグの話であり、納品側は上記で上書きする。
