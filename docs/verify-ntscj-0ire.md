# 黒レベルを 0 IRE に直す（--NTSCJ）

2026-11-13。マスターの指摘「S端子で見た映像の方が明らかに明るい。
ビデオデッキのエンコードの仕組み踏まえて暗くなってたりするのでは」から始まった。

## 何が起きていたか

`vhs-decode` は `--NTSCJ` を付けないと米国式 NTSC-M を前提にする。
米国のテープは黒が 7.5 IRE（セットアップあり）、日本のテープは 0 IRE。

    vhsdecode/main.py:775
      if system == "NTSC" and not args.ntscj:
          vhsd.blackIRE = 7.5

日本のテープに 7.5 IRE の下駄を履かせると、**0〜7.5 IRE の帯が
「黒より下」として書き出しの時点で切り捨てられる。**

## どこに効くか（重要・再デコードは要らない）

`blackIRE` が使われるのは2か所だけ。

    lddecode/core.py:3687   初期値 0
    lddecode/core.py:4974   vp["black16bIre"] = ...

**JSON のメタデータを書くだけで、復調にも TBC にも一切影響しない。**
つまり既にある `dec.tbc` を捨てずに、`dec.tbc.json` の `black16bIre` を
書き換えて書き出し直せば `--NTSCJ` でデコードし直したのと同じ結果になる。

    black16bIre  16243.2（7.5 IRE）  →  13824.0（0 IRE）
    white16bIre  56320.0  … 変わらない

幅が 40076.8 → 42496 になるので、書き出し後の値は

    out_new = 0.9431 × out_old + 58.24        （40076.8/42496 = 0.9431）

という **信号全体の一次変換** になる。輝度も色差も同じ比率。
tape05 の実測で Y 0.9431 / U 0.9430 / V 0.9428、理屈と小数4桁まで一致。

## どれだけ捨てていたか（tape05、全編685コマ 0.25G画素、等倍）

書き出し後の値は 0〜1023 で、床は 4。

              床(値4)に張り付いた画素
    7.5 IRE        14.61%
    0 IRE          11.45%      差 3.16%

真っ黒のリードイン20コマ（信号としての黒）:

              床に張り付き   99%点   σ
    7.5 IRE      100.00%       4     0.25
    0 IRE         89.78%      14     1.88

**7.5 IRE ではテープの黒のノイズの粒まで完全に潰れていた。**
0 IRE では信号として残る。

## 目盛り（黒点をどこに置くかの根拠）

JSON の3つの数字から、出力値と IRE の対応が解ける。

    blanking16bIre 15360.0   本物の 0 IRE（level_adjust がかからない）
    black16bIre    16243.2 = (15360 + 7.5*358.4) * (1 - 0.1)
    white16bIre    56320.0 = (15360 + 100 *358.4) * (1 + 0.1)
      → 1 IRE = 358.4、level_adjust = 0.1

書き出しは black16bIre→0、white16bIre→1023。--NTSCJ では
black16bIre = 15360*0.9 = 13824 なので:

    値  37 =   0.0 IRE   映像の黒
    値 102 =   7.5 IRE   米国式セットアップ
    値 122 =   9.9 IRE   standard-v2 の黒点68 と同じ見た目
    値 137 =  11.6 IRE   contrast-v2 の黒点84 と同じ見た目
    値 900 = 100.0 IRE   白

**白側で裏が取れている。** 100 IRE の予想値 900 に対し、マスターの
実測最大は 894。線形写像なので、白が合っていれば黒側の 37 も従う。

切り捨て量（tape05 全編 685コマ 0.25G画素、等倍）:

    黒点  4 = -4.3 IRE   11.45%   書き出しの床。これ以上は戻らない
    黒点 37 =  0.0 IRE   13.85%   ← standard-v4
    黒点102 =  7.5 IRE   16.1%
    黒点122 =  9.9 IRE   16.79%   standard-v2 と同じ見た目
    黒点137 = 11.6 IRE   17.37%   ← contrast-v4（contrast-v2 と同じ見た目）

## 黒点をどう決めたか（やり直した経緯も残す）

最初、のあは **床(値4)を真の黒だと誤解した。** level_adjust のぶん
黒より下に余白があり、床は -4.3 IRE である。これは訂正した。

最初に出した比較画像は **髪の黒**だった。マスターの指摘
「髪の黒だから正しくない可能性がある」が正しい。髪は本当に真っ黒なので、
そこに何か出るべきかどうかで判断できない。

やり直した比較（259.3秒、黒い上着＋十字架のペンダント＋布のシワ）で、
マスターが **「十字架の残り具合を見ると緑が正しそう」** と判断。
緑＝黒点37＝0.0 IRE。金属と布という既知の構造物で、潰れ始める境目が
はっきり出る場面を選んだのが効いた。

**2026-11-13、マスターの判断で standard-v4 = 黒点37（0.0 IRE）。**
contrast-v4 は 137（contrast-v2 と同じ見た目）を維持。
「オリジナル(標準)とハイコントラスト」という2本立ての軸が、
これで**情報を残す側と見栄えの側**にはっきり分かれた。

## 3つの帰結

1. **明るさ** … 納品の黒点で吸収されていた。実害なし
2. **色** … 同じ 0.9431 倍がかかっていた＝**6.0% 濃すぎた**。
   納品に彩度のつまみは無いので、黒点では戻せない
3. **暗部** … マスターの時点で切り捨て。0 IRE にしない限り戻らない

## 直した場所

    bin/vhsfinish:215      vhs-decode ... --NTSCJ ...
    bin/vhstool:184,240    同上（並列・単発）
    bin/vhsfinish:400付近  マスターに VHS_BLACK_IRE=0 のタグを書く
    bin/vhsdeliver:66付近  マスターとプロファイルの黒レベルが
                           食い違ったら止める

タグを入れたのは、7.5 IRE 時代のマスターに 0 IRE 用プロファイルを
当てても誰も気づけないため。名乗りが無いマスター／プロファイルは
7.5（古い側）とみなす。

## 直せないもの

tape01〜04 / 06 / 07 は RF も TBC も削除済み（2026-11-12）。
マスターの mkv しか無く、暗部は既に切り捨てられている。
色の 6.0% だけなら一次変換で戻せるが、それは二次加工になる。別途判断。

RF/TBC が残っているのは **tape05r と tape08 だけ**。
